# 验收记录

## 网页训练台

Windows 和腾讯云 Lighthouse 均在 Node.js 24 通过 26 项测试。网页集成测试覆盖登录、跨站写入拒绝、绑定隔离、活动 CSV 与 FIT 上传去重、功率 CSV 上传、Intervals.icu 响应替身和双向对话。复测还覆盖网页消息重发去重、关闭同步后跳过待发消息、会话失效保护，以及网页显示定时提醒正文。Edge 使用虚构骑手数据渲染概览、图表和课表。

云端网站通过独立 systemd 服务启动并与教练共用 SQLite。已核对受保护的仪表盘、`401` 未授权响应和云端 CSV 去重。手机发送「这周怎么练」后，网站读到了消息和教练回复。首次网页到微信测试取得 `channel_ok`，手机未收到，需按实际会话条件重试。重启网站后，训练档案和发送状态均可恢复。个人 Intervals.icu API 授权已实测，Strava 来源只返回占位，因此用骑手自己导出的活动 CSV 补录。实际绑定、域名和骑行记录均保存在部署环境。

### 投递证据

- `attempted` 有值表示调度任务已处理，包括因训练完成而跳过的情况。过程状态 `running` 表示已认领准备发送。
- `channel_ok` 表示发送适配器返回成功及消息标识。上游可能只给客户端生成的标识。请在手机会话确认是否可见。
- 以 `confirmed` 记骑手的手动回执。实机记录只保留脱敏版本、任务号、相对时间与结论。日志、微信 ID、二维码和档案留在部署环境。

到云端执行 `npm start -- jobs weixin` 查看任务及三类证据。若是通道成功但手机不可见，继续记录为手机未确认，并比较短、长间隔的表现。上游社区出现过此类情况。 [腾讯插件问题记录](https://github.com/Tencent/openclaw-weixin/issues/264)
